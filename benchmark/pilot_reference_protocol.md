## 足球关系诊断试标 v0.1（2026-09-22，待人工确认）

本节是当前 12 类 pilot 的统一操作定义候选，用于 AI 先填、人工逐项确认的诊断试标，不是已冻结的足球通用定义。保留现有 CSV 的标签、时间窗、原依据和润色正文；不覆盖词条库的历史版本，也不沿用旧识别实验中固定三秒的 restart 否决来自动改判本轮样例。候选定义获确认后，再单独迁移受影响的词条和实例。

### 统一判别边界

- 分开记录动作证据、战术结构是否具备、配合完成情况和后续结果。已经出现的传球或跑动不会因未射门而消失；只出现配合前缀也不能直接判定完整战术结构成立。
- `supported` / `contradicted` / `unknown` 是逐命题的机器判断；`not_applicable` 表示不适用。未提及、遮挡或窗口截断不能当作 `contradicted`。机器支持仍是 `machine_draft`，不等于人审 GT。
- 阶段分别写 `prefix_only`（只有前缀）、`pattern_observed`（判别结构已出现）、`completion_observed`（该类约定的接应或配合完成可见）、`unresolved`。射门、进球、夺回球权、越位和裁判处罚另记，不塞进同一个“成功”值；并非每类都有统一的完成终点。
- 所有位置和关系绑定执行队、动作主体、参照对象及时间段。本方/对方固定相对于执行队，左/右固定相对于该队进攻方向。局部防守者身后不等于整条最后防线身后；跑入身后不等于合法反越位。
- 保留半场作为基础位置，按可见程度增加通道、禁区内外、底线附近等独立属性，以及向内/外、向前/后、跨侧、线前/线后等关系。不强制 15 区、米级距离、精确人数或固定第三分区阈值。跨半场是可见路径，不是统一的不可观察。
- `Where` 评价场地锚点和相对空间关系；`Evidence` 评价动作、主体绑定和时序衔接。同一命题可以带多个诊断标签，但主统计只归属一项，不重复累计。后续结果用于事实忠实性审查，不自动成为每类的必需证据。
- 每条判断区分 `target_window` 与 `context_only`；窗外关键动作可辅助提出修窗建议，不能悄悄计为窗内证据。画面左/右仅作审阅定位提示，不能替代球队相对左右。

### 十二类候选定义与判据

下表中的编号在本轮固定，用于逐项审核；三个判据不是从标签自动生成的真值。正例、反例、前缀尝试及证据不足均可入诊断集，不能把尚未裁决的原标签争议当作已确认负例。

| --- | --- | --- | --- |
| `long-ball` | 从后场或中场用直接的长距离高球联系前方接应区域，绕过中间的逐点短传组织。 | LB1 后方或中场直接起高球；LB2 长距离连接前方目标而非附近短传；LB3 可见接应者迎球、追球或争点与该出球相连。 | 不要求赢得第一点、出现第二点或完成射门。地面长传不自动等于本轮“长传冲吊”；前场传中/定位球传入须与后场直接输送分开裁决。 |
| `line-breaking-pass` | 通过传球把球从一条可辨认防守单元线的前方送到其后方或下一线之前的接应空间。 | LP1 存在实际向前传球而非仅带球过人；LP2 球路穿越可辨认防守单元的覆盖；LP3 越线后的球路连接队友接应方向。 | 不限定地面球，不要求突破最后一线或形成单刀。只绕过一名上抢者不能自动写成穿透整条防线；不以精确米数或接球成功作统一门槛。 |
| `run-in-behind` | 无球队员由可辨认的最后防线附近跑向其身后，并与队友的出球方向形成联系。 | RB1 观察到跑者的启动或接续跑动；RB2 跑者相对于最后防线进入纵深；RB3 跑动与传球方向、时机对应。 | 合法越位位置、成功接球、最终终结均另记。只见局部防守者时将最后防线关系记未知；窗前启动不能回填为窗内观察。 |

| `switch-of-play` | 以一次传球或连续传递将球从一侧转到另一侧的宽位接应区域。 | SW1 可定位转移前球侧；SW2 实际传球或传递链横跨中间区域；SW3 连接另一侧接应方向。 | 不限定一脚高球，不要求接稳、摆脱全部防守或另一侧无人盯防。中路分边不是天然的跨侧转移；争抢后的偶然换侧另行裁决。 |
| `cutback` | 从禁区侧方较深、接近底线的位置，向内侧且相对出球点更靠后的接应区域回送。 | CB1 出球位于禁区侧方较深位置；CB2 球路相对进攻方向向内且向后；CB3 回送与禁区内侧的接应方向对应。 | 横扫门前不是自动倒三角；是否足够接近底线单列。高低球单独记录，不仅凭高球否决，也不要求射门、进球或固定两名包抄者。 |

| `short-corner` | 角球第一脚短距离联系角旗附近队友，而非直接寻找禁区内争点。 | SC1 角球启动可见；SC2 第一脚联系近处边路接应者；SC3 第一脚不是直接传向禁区目标。 | 后续回做、带球或传中均可，不强制第二脚立刻传中。仅见角旗附近配合不能反推角球第一脚。 |
| `back-line-possession-management` | 在本方后场通过多次横传、回传和重新接应维持球权、重新组织出球。 | BP1 后场接应点之间存在连续传递；BP2 出现横向/向后循环或回收；BP3 本队在该循环中保持或重新稳定控球。 | 允许局部向前推进、有对手施压及末段转入进攻；不要求全窗不越中线。仅一次回传不够，主动拖延时间不从慢传直接推断。 |
| `tactical-foul` | 对正在推进的对手实施有犯规依据的防守动作并中断其进攻；“战术性”作为需人工解释裁决的层级。 | TF1 对手正在推进或转换；TF2 可见防守接触及独立的犯规依据；TF3 动作与进攻中断直接相连。 | 倒地不等于犯规，犯规不自动证明主观目的；裁判抬臂不单独证明黄牌。可先确认接触和中断，再将犯规责任及战术解释交人工。 |

### 试标与审核

先在现有 pilot 内每类选 2 条，共 24 条，作为协议开发集而非独立测试集。优先组合典型过程、未完成过程、位置混淆或窗口缺口；套边仅有两条既有记录时全部纳入，不虚构内切套上样例来凑子型覆盖。

AI 先回看证据图，对核心判据和细化空间关系逐项填写候选值，附实际查看的图像、原视频路径、时间段和一句可核验的观察。人工只需选择“同意 / 修改 / 看不清”，并优先裁决标签或定义争议，不要求从零撰写长段落。人工选择及审核人/日期在未审核前留空。

试标不等于双人独立标注，也不产生人工一致率。候选定义、证据覆盖和未知原因先经审核，再决定是否扩展到 259 条；AI 复用旧草稿或旧审核记录的部分必须注明来源，不能冒充本轮新看的视频事实。

本轮已整理 [试标底稿](pilot_diagnostic_trial.json)，共 24 条、146 个审核项：72 个核心判据、48 个场地锚点/空间关系、16 个事实探针、8 个定义规则检查及 2 个窗外线索，引用 52 张实际查看的归档图像。审核项不等于互不重复的事实；核心判据与空间项可能复述同一观察，正式评分前须去重。事实探针是人工构造的检查命题，不是被测模型输出，不能据其真假比例汇报模型幻觉率；规则检查和窗外线索也不进入事实幻觉统计。

人工入口为 [Excel 审核表](../outputs/pilot_diagnostic_review/pilot_diagnostic_review.xlsx)，另有 [逐条可读稿](../outputs/pilot_diagnostic_review/pilot_diagnostic_review.md)。生成及只读检查由 [审核导出脚本](../scripts/pilot_diagnostic_review.py) 完成：`python -m scripts.pilot_diagnostic_review --check` 校验来源、判据覆盖、时间范围、证据路径和 Excel 往返内容；不带 `--check` 时仅在输出不存在时导出，拒绝覆盖已有人工意见。未逐帧连续看完整24段视频，实际复看范围以底稿各项的证据图为准。

整理期间用户修改了非试标行 `AA-train-103` 的 AI 末句，本轮未覆盖；当前试标来源指纹及变动说明保存在底稿的 `source_sha256` / `source_updates`。AA 历史发布指纹仅代表当时快照，不能用于断言用户随后编辑的 CSV 损坏；24 条选中记录仍逐项匹配既有参考账本。

### 参照与字段

- `reference_team` 固定为本条战术的执行队：进攻战术取进攻队，逼抢取施压队，后场控球取持球队，战术犯规取可见接触的防守方。后者不表示已经裁定其犯规责任。一次记录内不随球权转换更换参照。
- `own_half` 表示包含该队所防守球门的半场，`opponent_half` 表示另一半场。用中线与球员地面位置定位，不以屏幕左右、球衣颜色本身或空中球投影判断。
- 传跑类使用 `mode = origin_target`，分别标 `origin_half`、`target_half`；逼抢、战术犯规、后场倒脚使用 `mode = event_area`，只标 `event_half`。字段模式由战术规则预先确定，不由模型自由选择。
- 适用但不能赋单一半场值的字段为 JSON `null`，导出表显示 `unknown`；本模式不适用的字段在 JSON 中省略，导出表显示 `not_applicable`。两者不能混同，也不能把 `null` 当作不存在该事件。

| 战术 | 位置取法 |
| --- | --- |
| 长传、破线传球 | 本次传球起脚处 -> 首次可定位的接应或迎球区域；无需赢得球权，但不能仅凭空中球越线确定落点 |

| 撞墙配合 | 原传球者第一脚出球处 -> 同一球员追向或接到回送球的位置 |
| 大范围转移 | 转移前原球侧的出球处 -> 另一侧接应处，不以居后中继点代替整个转移起点 |

| 短角球 | 角球第一脚起点 -> 第一脚的近处接应者，不取后续传中落点 |
| 快速反击 | 窗内本次推进最早可定位的控球或向前出球位置 -> 本窗内该次推进的最后可定位位置；不回推窗外夺权，也不使用对手重新控球后的终点 |

## 三种粒度

| 层级 | 要回答的问题 | 输出字段 | 比较重点 |
| --- | --- | --- | --- |
| G1 动作事实 | 谁在什么时间、什么位置做了什么? | `facts` | 主体、动作、方向、区域与时间是否正确 |
| G2 局部关系 | 多个动作怎样连接，队友与对手如何相互作用? | `relations` | 动作顺序、接应关系、相对位置、对手反应是否有证据 |
| G3 片段解释 | 哪些事实具有战术判别力，过程实际发展到哪一步? | `interpretation`、`commentary` | 解释是否成立，是否把尝试写成完成，是否虚构效果 |

`interpretation` 是可审核的判别解释，`commentary` 是面向观众的自然表达。二者共享事实底稿，不是两个独立 GT。短、中、长篇幅可以以后从同一底稿派生，不作为新的事实粒度。

球队颜色用于指代。号码、精确人数不是统一必填项；确有判别作用且画面可见时写入对应事实。事实与解释正文不以战术名称代替证据。原始标签另存于 `source.tactic`，存在争议时须先裁决再作为正式标签真值。

## GT 使用条件

用户对原始 GT 工作簿的完整核验是原标签和原依据的人工来源，不等于已经逐项确认 AI 新增的动作、区域、关系和结果。`annotation` 中人审信息为空指 AI 扩写尚未记录审核，不是否定用户已经完成的原标注核验。

三层描述已覆盖粗粒度动作事实、时空位置、局部关系和战术解释，但它们是组织方式，不是穷尽性保证。部分事实句仍包含多个命题，`candidate_core_fact_ids` 也只是候选项。当前没有冻结逐项评分清单，不支持米级距离、精确球员坐标、精确越位线或仅凭先后顺序确定的战术因果评测。

正式使用前至少需要：

1. 为既定任务逐条确认可独立评分的事实，区分必需核心、可选细节、窗口外背景和无法判断项；依据视频补查遗漏，不能只从现有段落反向生成清单并声称完整。
2. 人工核对关系及其证据，裁决有争议的主体、区域、标签和窗口；对尝试、完成、成功分别判断，将确认结果与参考版本绑定。
3. 统一模型可见窗口和上下文、时间容差、空间粒度、语义匹配及部分正确规则；没有证据的意图不设为必答点，未标注的真实事实不自动判错。
4. 分别报告事实正确性、核心覆盖、关系正确性和解释忠实性，避免同一事实跨层重复加分；用人工裁定样本校准自动或模型评分，文本相似度不能单独代表事实正确。

当前可用于开发阶段的探索性评测，但须标为未冻结的机器参考草稿；不能据此宣称已具备完整多粒度 GT。正式 GT 应由审核后的结构化事实和评分要点承担，润色段落作为可读参考，不是唯一正确措辞。若评测还要求未给定窗口的事件发现或全片战术识别，则另需相应的时间定位和完整标注范围，不能把本次选定正例窗口当作全片穷尽标注。

## 共享输出约定

参考与被测模型都输出相同的 `output` 对象，字段如下:

- `clip`: 片段 ID。
- `target_window_s`: 原视频起点为 0 的目标窗口 `[start, end]`。
- `facts`: `id`、`span_s`、`text`。每条尽量只含一个可独立核验的事件命题。只记录模型愿意断言的可见事实，不写意图、标签或未核实的效果。
- `relations`: `id`、`span_s`、`text`、`evidence_ids`。引用本次输出中的事实，描述时序或空间关系；先后发生不等于因果成立。
- `interpretation`: `text`、`evidence_ids`、`relation_ids`。直接描述有证据支持的动作、位置与配合关系，用具体过程说明判别依据。证据不足和审核提醒另记于 `uncertainties`、`review`，不混入参考正文。
- `commentary`: `text`、`evidence_ids`。用自然语言组织已支持的信息，可以概括，不得增加事实。
- `uncertainties`: `span_s`、`text`。记录看不清、无法确认和窗口截断造成的缺口；无缺口时为空数组。

时间使用原视频秒数，不使用比赛计时牌，也不因裁剪视频而偷偷重置。已断言事实的时间范围须在目标窗口内；缺少时间依据时放入 `uncertainties`，不要编出时间戳。局部 ID 只用于内部溯源，被测模型的 `f1` 不需要对应参考的 `f1`。

事实层可以记录可见的否定事实，但必须限定观察范围。“没有看到”不等于“没有发生”，“未完成配合”不等于“没有尝试配合”。固定场上位置如“前锋”“中卫”若不能确认，改用“前方接应球员”“防守球员”。

引用 ID 不是正确性的保证。人工审核还要检查引用的事实是否真的支持关系和解释，不能只检查 ID 存在。

## 制作参考的流程

1. 保存 CSV 中的 `clip`、`tactic`、`interval`、`判断依据`，核对视频映射与目标窗口。
2. 观看目标窗口和预先规定的前后文，逐项检查原依据。记录支持、需收窄、矛盾或仍无法确认的内容。
3. 先写 G1，再依据 G1 写 G2，最后生成 G3。允许使用标签和原依据定位判别点，但不得把它们当作视频证据。
4. 新事实、原文更正、缺失证据单独记入 `review`，不把新增内容伪装成纯语言润色。
5. 人工回看并检查事实、关系、解释和标签，必要时修正或降级。完成后才设置 `annotation.status = human_verified` 并填写审核人和审核日期。

抽帧可以辅助定位，不能替代对快速触球、遮挡和争议动作的原帧率回看。`machine_draft` 不参与正式 GT 评分。GSR-001 开发样例以 4 fps 检查 15-24 秒，后补查 21.76-22.36 秒原帧；本批按上面的实际采样与补查方式记录。事实时间为近似定位，所有条目仍待人工复核，模型自检不升级人审状态。

参考记录中的 `source`、`annotation`、`review` 是制作与审核信息，不是被测模型应收到的答案。`review.candidate_core_fact_ids` 只是拟选评分要点，须经人工确认并在正式测试前冻结。

## 如何比较

- G1 按语义命题与时间对齐，不按字符串或局部 ID 相等。允许同义表达、合理拆分与合并；同一命题不能因重复表述多次得分。主体、动作、方向、结果或时序冲突都应单列。
- 人工冻结的可观察核心事实用于计算覆盖率。预测断言逐条裁定为支持、矛盾或待核验，报告各项数量及核验覆盖率；参考未提及的断言不能自动判错，须回看视频。
- G2 检查关系本身及其证据是否成立。事实都正确但关系错误，仍是关系层错误。时序关联不能自动升级为吸引、迫使、创造空间等因果断言。
- G3 分开评价判别解释的正确性、关键证据覆盖和解说忠实性。不得因语言流畅而宽免虚构事实，不把与参考措辞相似作为正确性的主要依据。
- 三层分开报告，不将同一底层事实在三个文本中重复计分后直接相加。短解说允许省略非核心细节；不能要求它逐字覆盖所有细粒度事实。
- 单列错误断言、合理弃答和过度弃答。参考与预测均不确定的部分不当作已知正例，但应报告不可观察比例，避免只留下容易片段。
- 目标窗口外发生的真实动作不计入本次目标；若要评价后续结果，先统一扩展参考与模型输入协议，再重做标注。

当前尚未实现自动评分器，也没有得到模型比较结果。先用已人工核验的小样本校准语义匹配、时间容差和判定标准，再冻结正式评测。
